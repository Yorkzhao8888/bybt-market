# 【X-MARKET-TI-02】内测版质量修复（登录态 + 审计口径 + 治理看板联动）P0

## 背景
X-Market 内测版（TI）已上线（部署 7f8dfaea，验收全绿）。测试侧在深度数据积累与全链路验证中发现 3 个影响内测体验与数据可信度的问题，本单一次性收口。

## 范围（本单只做这 3 项）

### 1. 登录态有效期（内测体验阻断）
- **现象**：token（`xm_` 前缀）约几分钟内失效，长链路操作多次被迫 re-login；自动化用「每次操作前重新登录」规避，人工与自动化均有摩擦。
- **要求**：内测环境登录态有效期放宽至 ≥2 小时；若已有刷新机制请确认生效，没有则补简单的过期续期（或按 OAS JWT 口径对齐）。不改变 quick-login/oneclick 一键登录通道。

### 2. 审计与业务口径一致（合规疑点）
- **现象**：VEM 审批 o-1017，业务侧返回「仅待治理审批的采购单可审批」失败，但审计中却出现 `order_approval allowed` 留痕（pa-20）。
- **要求**：确认业务校验与审计落库口径——业务失败不得落 `allowed`；业务成功必须留痕。给出权威口径并修正不一致处（历史脏数据可标注，不强改）。

### 3. 治理看板审计覆盖度联动（疑似回退）
- **现象**：治理看板审计覆盖度 0/19（19 项动作 0 覆盖），但 EU/VEM 侧「我的留痕」22 条并存——审计数据在持续产生，看板不联动。
- **要求**：修复治理看板审计覆盖度统计口径/联动，恢复与「我的留痕」一致；确认是否与 X-MARKET-ERP-01 嵌入改造相关，如是则回归不破。

## 红线
- 不改变 HAT_MATRIX/权限语义、不动三权 checkPower
- 零新端点优先（复用现有审计/统计能力）
- 内测版认证放行口径不回退（业务类匿名放行 + 一键登录标配）

## 验收（3 条）
- V1 登录态：一键登录后 ≥2h 内不失效；跨页面/刷新保持；回归 quick-login/oneclick 全角色 200
- V2 审计口径：失败审批不再落 `allowed`；业务成功必有留痕；o-1017 类场景给出明确口径
- V3 治理看板：审计覆盖度恢复（与「我的留痕」一致）；19 项动作有覆盖；回归五页面 + 登入端 V1-V7

完成后贴 40 位 commitHash + 提交信息 + 变更文件清单，确认工作区干净；凭证齐后主 Agent 统一部署线上验收。
